client. Its package includes the shared session router and subscription engine;
the runner mounts only the completed package.

## Running it

[Install and run](../../../docs/agents/slack.md#installing-it) through the runner.
`package.sh` bundles the client, router and worker into a flat agent.d package.
No runtime import may reach back into the checkout. A package digest change
restarts the kept process on runner reload.

## Reply routing

See the [user contract](../../../docs/agents/slack.md#configuration).
`../shared/router.ts` owns tags, expiry, sender/correlation checks and audit.
`routing.ts` adapts exact Slack timestamp strings and addressed-event selection.
The bounded, deduplicated forwarder queue runs routing before independent
subscription matching. Own-post detection (bot user, bot id or app id plus
Posted) precedes both, including API/Socket races. Routing retry exhaustion
never skips subscription matching.

## Compatibility

`postas.ts` retains runner-env defaults and legacy Secret defaults for
SLACK_USERNAME/SLACK_ICON; these are not routing Configuration keys.
Token and workspace contexts stay per call; API errors are scrubbed before
answers or logs. Counter persistence remains batched independently of routing.

## Tests


`bun test ./src/agents/slack` runs everything against a real daemon (built
here, or `SMOKE_BIN`), the actual agent, and a fake Slack with a Socket Mode
websocket — no network and no real tokens. `src/smoke.sh` runs it as
the `agent_slack` shard.

## Authored help

`agent.json` owns methods, typed arguments and Configuration descriptions.
`env.dist` owns environment-key comments. Package help is generated by the runner;
self-serving and bare-process help uses the shared manifest helper instead of
a second method list. Bundled agents omit `version` and use the bus version.
Executable-grammar checks compare the methods with generated help.
