# Changelog 0.5

📌 **TL;DR:** Archived changes **0.5.0–0.5.84**, 2026-09-13–2026-09-18, grouped by area. These describe the behavior at each transition, not the current contract. Next: [0.6](CHANGELOG.0.6.md#changelog-06).

## Grouped changes

| Area | Versions | Summary |
|---|---|---|
| Programs and AI sessions | 0.5.0–0.5.13 | Established one version/build stamp across Go programs and MCP, process-title observations, Claude/Codex launchers and an OpenCode adapter. Added local socket discovery, template/instance names, explicit session bindings, coordinated renames and terminal-title restoration for distinct sessions. |
| Identity and lifecycle | 0.5.17–0.5.35, 0.5.55–0.5.59 | Removed names released their reservations and credentials (0.5.17); unknown principals could neither act nor obtain credentials, and orphan chains/stale memberships were removed. Suspended owners' records refused work without losing state. Daemon ownership and OS-account mappings became durable, with setup seeding rather than overwriting them. |
| Access and administration | 0.5.21–0.5.32, 0.5.43–0.5.62, 0.5.74 | Protected administrator membership and onboarding; removing administrative standing retained the User. Nested groups resolved without cycles widening access, Maintainers became an owner-assigned principal list, and `@owner` sharing replaced the master layer. Empty ACLs retained only explicit owner/Maintainer/own-inbox authority. Group deletion was refused instead of decoded as an empty-membership save. |
| Durable management and messaging | 0.5.19, 0.5.31–0.5.37, 0.5.47, 0.5.52–0.5.53 | Management success followed durable writes and caller authority was checked under the write's hold; failed persistence left authority unchanged, and transfer/removal/credential changes became atomic. Consume separated inbox selection from topic/tag filtering, removing the address-shaped topic overload; reader counts included filtered reads. Full queues returned 429, and refusal counters distinguished caller refusals from internal faults. |
| Personal records | 0.5.50–0.5.51 | Added an owner-controlled classification and dedicated grouping without granting message authority. Restricted policy changes were validated together; metadata refresh preserved the owner's choice. |
| Runtime isolation and transport | 0.5.18–0.5.20, 0.5.26, 0.5.45–0.5.49 | Requested web TLS failed closed, web received no inherited bus credential, SSH token commands were restricted and launcher-owned Codex servers required a private capability. The then-Go dashboard gained filesystem/process confinement and a resource-limited cgroup; unavailable confinement did not start an unconfined child. |
| Packaging and recovery | 0.5.32, 0.5.68–0.5.69 | Shipped a verified self-contained archive and digest-addressed install. Upgrades staged and health-checked the new release, backed up matching state and recovered the prior release, credentials, registry and queues after failure/interruption. Onboarding created both the key entitlement and registered person. |
| Dashboard and diagnostics | 0.5.7, 0.5.14–0.5.16, 0.5.24–0.5.42, 0.5.54–0.5.84 | Added caller-scoped user/group/account and service/channel journeys, a shared responsive accessible shell, safe form refusals and confirmed dangerous actions. Separated declared policy, observed readers, delivery and health; added bounded activity graphs, correlation-aware diagnostics, counts, filters and pagination. Local GitHub metadata/photos avoided per-row provider reads. At 0.5.84 the then-`agent` record was presented as an inbox rather than an external service, an interim classification replaced in 0.6. |
