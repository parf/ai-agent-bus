# Administrative crash recovery

📌 **TL;DR:** H.5.3 saves administrative changes before success; a bus crash cannot undo an acknowledged restriction.

## Scope

Implemented for 0.5.47 against the settled
[administrative recovery contract](../../../docs/04-messaging.md#administrative-crash-recovery).
The existing snapshot port is bound by the daemon. Core holds its operation
lock through snapshot capture and save, including periodic and shutdown writes.
This prevents an older checkpoint from replacing a newer acknowledged policy.

The JSON adapter writes a private temporary file, synchronizes it, renames it
over the snapshot, and synchronizes the parent directory. The periodic writer
is joined before the clean shutdown checkpoint. No new snapshot schema,
transaction log or caller credential is introduced.

Failure returns an error instead of success. Applied memory changes are not
rolled back: a failed ban write does not restore the caller's access. A later
explicit retry can establish the durability that the failed request did not
promise. A failed operation may also be captured by a later checkpoint; the
error is not a claim that nothing happened.

## Checks

`src/acceptance/administrative-durability.py` uses a real disposable systemd
unit generated by setup, with separate state, runtime paths and credentials.
Periodic snapshots are explicitly disabled. The harness kills the actual bus
child after each successful administrative response and waits for its replacement.
It never kills the live daemon or writes its state.

| Case | Before crash | After crash |
|---|---|---|
| Ban | Existing token, session and mapped socket work; acknowledged ban immediately refuses the session | Old token and mapped socket remain suspended |
| Group removal | The same three access paths work through group membership; removal is acknowledged | Old token and mapped socket lose resource access |
| ACL tightening | The same three access paths work; replacement ACL is acknowledged | Old token and mapped socket remain excluded |
| All three | An unrelated user has its own credential and grant | That user still sends successfully; existing sessions are invalid, as expected for a new bus process |
| Storage failure | A directory replaces the disposable snapshot target, causing a real rename failure | Ban answers 500; memory remains restricted; storage repair plus explicit retry succeeds and survives another kill |

The mapped caller is the installed runner OS account, using its explicitly
named **disposable** socket. Owner calls and visitor calls use explicit shared
socket addresses. Fixture setup and restored-user positive controls prevent
"nobody can call after restart" from satisfying a refusal check.

Core checks also recover directly from the writer's last received snapshot,
without a final save after the returned success. They cover both user-state
routes, groups, management ACLs, registration refresh ACLs, record removal,
configuration, self-unsubscribe and manager subscriber removal. Each route has
a failed-writer control. The API check verifies 500 and an explicit successful
retry; the file adapter checks replacement, permissions and failed-write handling.

0 failed**, vet and race green (`slow-final.log:931`, lines 10–11). Every

## Mutations

Replay and logs: `tmp/admin-durability/mutate.py` and `mutations.log`.

| Mutation | Scope and named failure |
|---|---|
| Skip persistence in each of nine administrative routes | Targeted core test: acknowledged change was not recovered |
| Skip ban, group-removal or ACL persistence | Three additional real-unit runs: the old token regains access after the crash |
| Release the core hold between capture and write | Targeted concurrency test: administration returns before the older checkpoint completes |
| Swallow persistence failure | API test: failed persistence answers 200; additional real-unit run: disk failure acknowledges the ban |

Eleven distinct mutants: eleven targeted package runs and four additional
real-systemd acceptance runs. The full smoke suite is separate, not run per
mutation. Every listed run fails its named assertion.

The concurrency fixture blocks only the first save and permits later save
attempts independently. Its initial `sync.Once` implementation would itself
have serialized writers and masked the bug; that fixture was corrected before
the recorded mutation run. The snapshot-memory fixture also clears its decoded
destination before each replacement, avoiding JSON reuse retaining an omitted
old subscription. These were test-fixture defects, not production fixes.

## Limits

The installed checks use this host's actual systemd and existing service
accounts, with disposable paths. They do not close fresh-host installation,
upgrade recovery, runtime sidecar isolation, resource limits or browser gates.
Session invalidation after a crash is not evidence that the access restriction
persisted; the separate old-token and mapped-socket checks establish that.

File and directory synchronization is implemented, but no hardware power-loss
experiment or cross-filesystem certification is claimed. Individual message
acknowledgements retain their existing durability and at-most-once semantics.
