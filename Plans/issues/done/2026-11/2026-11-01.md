## Gate

- ✅ J74 the database fixture's own conmon can write a cgroup warning to the host journal
  - Fix: `962ce664`; test tooling only, no version bump. Owner: `#ab-w2c`, reader assigned by `#ab-lead2`.
  - Original report: in the 62-shard `src/smoke.sh --slow A,C,E,H` on `516fae57`, `agent_db` failed `test_fixtures.Journal.test_a_fixture_container_writes_nothing_to_the_journal`. The first report attributed it to a systemd “Started libpod-conmon-….scope” line and overlapping Podman use. That attribution is disproven: those manager entries carry only a container ID, not the fixture name. The same test passed twice alone at 14:18 on `4a9b8ff8`, and in the earlier `36d43221` slow pass.
  - Retained evidence: the actual matching field is `_CMDLINE` on a **conmon** entry, naming `ab-db-fixture-2493600-53733048-44025` from the T-23 slow tree. Its `MESSAGE` is “Failed to open cgroups file: …/libpod-<CID>.scope/container/memory.events”, with `SYSLOG_IDENTIFIER=conmon`. The warning at 14:14:01.447735 EST follows a cgroup-file read/removal race, not an unrelated container's scope-start message. Original T-23 terminal output was not saved, but this native journal entry was retained.
  - S1 observation limit: the same kind of warning is retained at 14:27:09.882228 for container `ab-db-fixture-3076855-53812279-50413`, while `tmp/ab-w2b-keep/s1slow.log:2898` reports the Journal test green. The outer `journal-quiet.sh` checks only `CONTAINER_NAME` and `PODMAN_NAME`, so it cannot see a name present only in `_CMDLINE`. The unittest checks one exact container after its own cursor; the old passing test did not retain that name/cursor, so the evidence cannot distinguish another fixture in the same process from a warning outside its window. The new deterministic case places the native warning inside this exact test's observation.
  - Reproduction: the original test stayed green 5/5 beside 77 tiny containers under other names. A test-only native interposer then returns `ENOENT` only for conmon's `memory.events` read, reproducing the retained warning while real PostgreSQL remains healthy and writes its own capped log. The journal assertion fails for both systemd and cgroupfs. Strace confirms cgroupfs still opens `memory.events`; it is not the fix, and no new delegated-cgroup dependency is added.
  - Config first: with Podman 5.8.9, a fixture-private `CONTAINERS_CONF`, explicit `--syslog=false`, and `--log-level=error` all retain conmon's `--syslog` in execve traces. The last changes its level, hiding warnings but still routing errors to the host. Installed configuration exposes conmon path/environment, not a switch for this channel; the user's global configuration is untouched.
  - Shared fix: `src/agents/db/fixtures.py:podman_command()` is used by every Podman call and detached removal, and is shared with the real-Qdrant fixture. It atomically creates a private temporary wrapper and passes it with `--conmon`; the wrapper strips only `--syslog`, forwards every other argument, and preserves existing stderr. The detached monitor's `nwarn` message is syslog-only, so suppressing it does not invent a replacement stderr message. Native conmon setup-error stderr remains observable. No journal filter exclusions, cgroup-manager change or logging-level change.
  - Permanent regression: `Journal.test_conmon_cgroup_read_failure_stays_in_the_fixture_log` runs at **normal and slow agent_db**, not fast. It compiles `conmon_fault.c` into the common checkout's shared `tmp`, not the worktree, and cleans it afterward. Missing `cc`, compiler failure, or an absent preload marker fails loudly; none silently skips. The marker proves the native read was intercepted, and the unsuppressed mutant exposes the actual monitor warning through the same journal assertion. Failure output now includes the matching entry's fields, including `_CMDLINE`.
  - Proof under a separately acquired and confirmed lock: removing only the wrapper's `--syslog` suppression compiles and fails on the real conmon entry; sources restored. The restored injected-race case passes **10/10** alongside **100 tiny containers**. Real PostgreSQL/ClickHouse tests pass **15/15** (11.076 s); all fixture checks pass **35/35** (23.479 s), including kill-during-startup, SIGKILL and SIGTERM watcher cleanup. No fixture container outlives its test. Lock released after the batch.
