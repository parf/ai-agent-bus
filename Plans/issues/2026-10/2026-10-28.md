# Issues — Oct 28, 2026 · seen while deploying the database proxy

Bug reports from live use, not a range review.

## Runner

- ⚪ R1 `src/cmd/agent-bus-runner` an installed agent that is not configured yet makes the whole runner report "degraded"
  - Evidence: `#db` installed on 2026-10-28 with no database configured and `DB_USER` required in `env.dist`: state `refused: needs DB_USER`, runner "degraded: 3/4 running"
  - Impact: noise at install time; an operator reads "degraded" as a fault and a real failure hides behind it. The same holds for any package with a required key
  > 💡👾 Report a refusal caused only by a missing required key as `unconfigured`, counted apart from degraded; the db package no longer declares `DB_USER` required, so it is not affected.

## Gate and landing (AB2, B.17/B.22 packaging)

- 🟠 G1 landing script `git merge --ff-only` chained after `smoke.sh --normal` with `;` — e2f9dce3 landed while the gate was red
  - Evidence: gate 1211/1, `go race` failed `TestBundleMustBeCompleteBeforeInstallation` (its own contract list lacked cron/at); fixed by e7fad21b, gate 1212/0
  - Impact: main carried one red Go check for ~10 minutes; anyone gating in that window saw a failure that was not theirs
  > 💡👾 Land only on `rc=0` (`… ; rc=$?; [ $rc -eq 0 ] && git merge --ff-only …`), as AB2 does from now on.
- ⚪ G2 `src/agents/standalone/logwatch/test_logwatch.py:179` the journal permission-error test races under gate load
  - Evidence: one `--normal` run got `'journalctl exited 1'` instead of `permission denied`; 5 of 5 runs alone pass; the next gate passed
  - Impact: a rare false red in any gate that runs agent_logwatch
  > 💡👾 Wait for the fake journalctl's stderr line, not only its exit, before asserting the reason.
- 🔴 G3 `src/agents/package.sh` packs `agents/db`, which setup's `bundleFiles` does not list — a fresh install from any archive built here is refused
  - Evidence: RT31 container run of `agent-bus-setup` from a `src/package.sh` archive: "package manifest names agents/db/agent.json, which is not a release artifact" (first `agents/db/support/lib/psycopg_binary.libs/libkrb5-….so`, the host's psycopg copied in by `db/package.sh`)
  - Impact: every release install since 0.9.129 fails before touching the host; a checkout install is unaffected
  > 💡👾 Manager: AB drops `agents/db` from the release archive until the owner decides how native psycopg libs ship, and adds a check that every agent `agents/package.sh` packs is in `bundleFiles`.
