## Test isolation

- ✅ 🟡 J97 hand-run tests from a launcher shell reached the live bus.
  - Evidence: the J13 test `src/launchers/no-bus-restart.test.ts` registered 3 records on the live bus; they were unregistered by hand. The Go CLI tests in `src/cmd/agent-bus` read the shell's `AGENT_BUS_SESSION_FILE` and called the live bus, which refused them.
  - Cause: the launcher and CLI discover the account socket (`/run/agent-bus/user-<account>.sock`) when no address is set, and a launcher shell exports `AGENT_BUS_SESSION_FILE`, which the CLI now prefers.
  - Impact: a test run from a session could register, send or be refused as a real identity.
  > 💬👾 Fixed: the J13 test puts a failing `id` on `PATH`, so no account socket is found (`e707580a`); the CLI package's tests unset `AGENT_BUS_SESSION_FILE` unless a fixture sets it (`0be0bcb8`); `src/smoke.sh` already strips every inherited `AGENT_BUS_*` but `ROLE` and `FDS` (`7d7ce99c`); the agent guide's `lib.sh` unsets it (`eea2cf6f`). Rule: hand-run tests from a launcher shell use `env -u AGENT_BUS_SESSION_FILE -u AGENT_BUS_TOKEN`.

- ✅ 🟡 J103 the slack and telegram test suites dial the providers' real APIs with fixture tokens.
  - Evidence: W2B's J97 trace counted 58 outbound :443 connects from the slack suite and 6 from telegram. `src/agents/telegram/t1.test.ts:227` and `:257` set no `TELEGRAM_API_URL`, so they reach `api.telegram.org`; the slack dials come from `slack.ts` agent processes that default to `https://slack.com/api/`, the test not yet pinned. Every token reachable is a fixture, so the worst case is a refused 401 or `invalid_auth`, never a send.
  - Impact: tests depend on the internet and on the provider's answer, and a future test given a real token could send.
  - Fix scope (#ab-dir): fake API bases for those tests; the slack and telegram `apiBase` helpers refuse a non-loopback host under a test flag, so a new dialing test fails instead; the guard turns today's dialing test red, and the fake base turns it green.
  > 💬👾 Landed as `89e44e47`: the slack dials were SocketMode WebSockets to the fake's team URL, so the fake now refuses `apps.connections.open`; telegram's tests use fake bases; a test-only flag makes the API and WebSocket dial points refuse any non-loopback host. Each dialing test went red under the guard and green with the fake. Reader: `#ab-w2a`.
