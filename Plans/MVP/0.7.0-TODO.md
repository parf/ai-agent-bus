## Objective

Deliver the [constitution](../../docs/constitution.md#project-constitution) in
the shared 0.7 release line. The constitution owns the model; this file owns

and user guides as each change lands. Existing [MVP acceptance](TODO.md#remaining-work)

## Starting point

Source review at 0.6.16: records and credentials use name references; Groups are
membership lists; records carry `disabled`; Service secrets accept nonempty
bytes. Administrative writes checkpoint before success but may mutate memory
before persistence. Five kinds, nested membership, Personal restrictions,
compacted JSON configuration and PubSub Deliver-To already have implementations.

## Next step

Start K.1, then the SQLite adapter in K.1.1 and K.2–K.5. Settle [forwarding details](QUESTIONS.md#constitution-forwarding)
before K.15; unrelated work can proceed. A reload API/SIGHUP remains optional
under the constitution and is not a required new feature here. If added, it
must pass the restart-equivalent queue/reader and complete-view checks in K.2–K.3.

## Verification

SQLite replaces the persistence backend without changing the accepted queue
checkpoint/loss boundary or persisting live readers and browser sessions.

Each behavioral change requires `src/smoke.sh --slow`, including vet and race
checks. Every credited mutation must compile and fail a relevant assertion;
test rejection, concurrency and persistence through the actual changed paths.
Installed gates remain separate from unit/handler tests. Planning-only edits
require link, scope, dependency and question-migration checks; no runtime version
bump or test-suite rerun is required for this file.
