## Verification

Apply the [0.7 architecture requirements](../../docs/10-modules.md#07-implementation-requirements)
throughout K.1–K.16. K.1 records a reproducible performance baseline; K.17 compares
lookup, authorization, management writes and concurrent send/consume at increasing
registry and backlog sizes on SQLite. Record latency, allocations, write
volume and lock contention. Check that an isolated record edit, including
ownership transfer, does not rewrite unrelated records or queued messages.
Agent/record removal is the explicit exception: its transaction removes every
stored reference to the removed name before publishing the complete view, so
later name reuse inherits nothing. Ownership transfer publishes a complete view
without a storage reload; no reload may appear on lookup, authorization or
delivery paths. Registry/authority reads do not query storage.
Investigate regressions and record justified tradeoffs before release.

K.3/K.5 implement [batched statistics persistence](../../docs/10-modules.md#statistics-persistence).
Use a controlled clock to count writes during traffic bursts and idle periods:
flushes follow the defined cadence, increments cause no individual writes and
empty flushes write nothing. Verify concurrent increments, retry without duplicate
counts, graceful shutdown and last-use timestamps. Include PubSub router counters
in successful-checkpoint restart, graceful restart and failed-flush retry checks;
verify their documented crash-loss boundary without creating a PubSub queue. Data changes commit immediately
without waiting for the statistics flush.

SQLite owns queue contents and their durable counters while retaining the
accepted one-minute/graceful-shutdown checkpoint and crash-loss boundary. The
0.6 JSON dump and credentials are not imported by the clean reinstall. Live readers and browser
sessions remain process-local. Storage checks must exercise real SQLite.
The [additional backends](../R1/storage.md#backends) are R1 work.

**Review cadence.** Every ten commits on the 0.7 line, counted from the 0.7.0
commit, a Fable reviewer reads the code and docs changed since the previous
review; one more full review precedes the STABLE commit. Findings are
reproduced before they are accepted, and fixed or recorded as pending work.

Each behavioral change requires `src/smoke.sh --slow`, including vet and race
checks. Every credited mutation must compile and fail a relevant assertion;
test rejection, concurrency and persistence through the actual changed paths.
Installed gates remain separate from unit/handler tests. Planning-only edits
require link, scope, dependency and question-migration checks; no runtime version
bump or test-suite rerun is required for this file.
