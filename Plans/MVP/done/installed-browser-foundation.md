# Installed browser foundation

📌 **TL;DR:** Real Chromium proves the installed session and restart contract;
the full role/action browser matrix remains open.

## Scope

The package-only fresh-host fixture installs distribution Chromium and Python
Playwright as acceptance dependencies, then drives the actual installed
dashboard. The browser and driver are fixture tools, not release artifacts.
The host keeps runtime networking disabled and mounts only the archive, fixture
and evidence directory; it does not mount the checkout or `/rd`.

This is partial F.12 evidence. It covers the common shell and session lifecycle
before the owner approves the remaining F.13 designs. It does not claim the
Owner, Administrator, resource Owner/Maintainer and ordinary-user action matrix,
redesigned journeys, TLS, multiple browser engines or runtime integration.

## Checks

The accepted run uses Chromium 153.0.8010.36 on systemd 261.3 at a 375 × 820
viewport against the plain-loopback scheme generated by setup.

| Journey | Measured result |
|---|---|
| Visible sign-in | Chromium enters the fixture Owner token in the rendered password field and the signed-in shell reports `owner@fresh` |
| Cookie boundary | Exactly one session cookie is `HttpOnly` and `SameSite=Strict`; it differs from the token, and the token appears in neither URL nor rendered page. `Secure` is false on this plain-HTTP installed fixture; HTTPS acceptance remains separate |
| Current required pages | Diagnostics, Services, Personal, Channels, Users, Groups and Activity each render one title while preserving the signed-in identity |
| Web restart | The real confined renderer PID is killed and replaced by the supervisor; the same browser session stays signed in because the bus owns it |
| Bus restart | The bus PID is killed and replaced; the old browser session becomes anonymous because sessions are process-local |
| Sign-out | The visible sign-out returns to sign-in, and replaying that newly signed-out session in a fresh browser context remains anonymous |

Screenshots, route titles, cookie properties and before/after process IDs are
under `tmp/installed-browser-20260918a/baseline-final-2/evidence/`. The credential
stays inside the disposable container and is neither logged nor mounted into
the evidence directory.

The first browser run receives no credit: the Arch fixture performed a partial
package upgrade, so Python required a newer glibc than the base image supplied.
The image now uses one full `pacman -Syu` transaction. The next run and the
strengthened sign-out rerun pass the whole package journey.

## Mutations

Six isolated source overlays each build a package and run a new real-systemd
host. Final result: **6/6 caught**.

| Change | Named failure |
|---|---|
| Make the session cookie script-readable | `HttpOnly` assertion |
| Replace strict same-site handling with Lax | `SameSite=Strict` assertion |
| Clear only the browser cookie on sign-out | Replayed server session still authenticates |
| Put the typed token in the redirect URL | Token-in-URL/render assertion |
| Kill the bus where the journey says web restart | Signed-in-session survival assertion |
| Leave the bus alive where the journey says bus restart | Replacement-PID assertion |

Replay and logs are under `tmp/installed-browser-mutations.py`,
`tmp/installed-browser-mutations-final.log` and
`tmp/installed-browser-mutations/`. The process-target mutations are harness
mutations: they prove that the two restart claims are attributed to distinct
real processes rather than to two page reloads.
