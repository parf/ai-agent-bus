# TODO 0.6.0 — record kinds

📌 **TL;DR:** `kind` becomes a closed set of five, `mode` retires into it, a service is an external one that is not on the bus, and 📡 carries secrets in a field of their own.

## Objective

Close `kind` so the daemon answers what a record is instead of a page guessing
it. The design was settled with the owner in discussion; this file holds the
unfinished work and its acceptance. Substance moves to the owning `docs/`
section as each row lands, and decision names to
[decisions](../../docs/decisions.md#settled).

There is no compatibility obligation before 1.1, so **no migration is written**:
the seven records on the live node are registered again with their kind.

## The enum

| Wire value | Glyph | What it is |
|---|---|---|
| `user` | 👤 | the queue a person reads |
| `agent` | 👾 | the queue an agent reads |
| `queue` | 📮 | a registered queue, named for its own sake |
| `pubsub` | 📣 | a pub/sub channel; keeps nothing, copies to subscribers |
| `service` | 📡 | external, not on this bus; nothing is delivered |

**This plan is taxonomic only.** The kind says what a record is. It does not
give a record a reader the daemon enforces: one allow list still governs both
directions, and `ConsumeAs` still lets an admitted caller drain a record named
after somebody else. Splitting that list is [Q74](../Future/acl-direction.md#where-direction-is-needed)
and **J.1 must not implement any part of it**.

Wire spellings are the lowercase forms already used by `topic` and `agent`;
`service` is fixed by the owner. Say the word and any of the other four change
before J.1 lands — afterwards it is a wire edit.

`generic` and `topic` disappear. ⚙️ stops meaning a record and stays with the
daemon (`agent-busd`, `docs/user/`).

## Remaining work

| ID | Deliverable | Depends on | Acceptance and mutation |
|---|---|---|---|
| J.1 | `kind` is a closed set | — | `register --kind banana` is refused, naming the five. Each of the five registers. Drop the validation and the `banana` check fails. Restore is J.11 and is not covered here |
| J.2 | `mode` retires | J.1 | `topic create --kind pubsub` is gone; 📮 and 📣 are registered by kind alone. No stored record carries `mode`, and the field leaves the wire. Leave `mode` populated on a 📣 and a check that the field is absent from `ls -j` fails |
| J.3 | `register` defaults to `service`, a script is an `agent` | J.1 | `register x@h --addr a --protocol p` with no `--kind` stores `service`. `agent-bus start` stores `agent` (`start.go:80`), and the started script still serves its inbox. Revert either literal separately and its own check fails — the two are independent edits, not one |
| J.4 | 📡 requires an address | J.1, J.3 | `register x@h` bare is refused; with `--addr` and `--protocol` it succeeds. Editing an existing 📡 to clear `protocol` **and separately to clear `addr`** is refused, not silently accepted, each with its own check and mutant — the check lives where `validatePersonal` lives, on the final record. Remove the edit-path check and the register check still passes while the edit check fails |
| J.5 | `--personal` is `agent` + flag | J.1 | A personal record is `agent`; `Personal` on any other kind is refused. Allow on a personal agent admits only other agents, and refuses a user, a group, `@owner` and `*`. Each forbidden assignment class has its own check &mdash; a user, a group, `@owner`, `*`, self and a non-empty Maintainers list &mdash; beside the positive case of another agent. `Personal` is refused on each of the other four kinds, not only on one. Restore the old `"generic"` literal and the personal-agent check fails; drop any one forbidden class and its own check fails |
| J.6 | 📡 holds secrets | J.1, J.4, Q77 | A **new field, not [Config](../../docs/03-services-and-topics.md#configuring-a-template)**: shell `KEY=value` text on a `service`, where Config is JSON on a template and stays readable by its own record alone. A secret is returned to whoever the record's ACL admits and refused to everyone else, with no second list; the secret **body** appears in no listing, no record answer, no page and no log, while the digest is present in each. A secret survives a restart, and a write is acknowledged only once it is durable. Every surface is pinned separately: `ls -j` and the record endpoint carry the digest **and** lack the bytes, the web detail redacts, and the daemon log never contains them. Remove the read check and the refusal check fails; return the bytes from `Public()` and the listing check fails; skip the checkpoint and the restart check fails; store a secret on any kind but `service` and that check fails |
| J.7 | Faces say what the enum says | J.1–J.5 | An agent's record is labelled `👾`, not `📥 Inbox`, and stays with the channels. Channels lists 👤 👾 📮 📣 and Services lists 📡 alone. `/personal` groups channels. `/services` carries 📡, and ⚙️ appears on no record. **The machine surfaces stay plain**: JSON, URL and form values, `--kind` arguments and ACL terms gain no glyph, each checked on its own. Point any one page at the old partition and that page's check fails; emit a glyph into any machine surface and its check fails |
| J.10 | The target's own user state is asked only where it exists | J.1 | `suspension(to)` asks `active(r.Name)` of a `user` and an `agent` and of nothing else; a `queue`, a `pubsub` and a `service` are sent to without consulting a user state they cannot have. Positive checks for `user` and `agent` where the state exists, negatives for `queue`, `pubsub` and `service` where it cannot, and owner suspension asserted across all five, since it is unchanged. Ask the own-state question of a `queue` and that check fails; drop it for an `agent` and that check fails |
| J.11 | Restore has a stated rule for a kind it does not know | J.1 | A snapshot holding `generic` or `topic` is not silently accepted: restore refuses with a message naming the record and the kind, and the daemon does not come up pretending the state is current. Accept an unknown kind at restore and this check fails; refuse at register only and it still fails. Closing `kind` without this leaves a daemon that boots on state it cannot describe |
| J.12 | Cutover runbook for the live node | J.11 | **Writing it**, which needs only the restore rule. Re-register the seven records under their kinds with **Owner, ACL, Maintainers, Personal, Config and queued work preserved**, and state the order relative to the incompatible restart. Verified by doing it on a copy of the live snapshot and diffing every one of those six against the original. Drop any one of the six from the procedure and its diff check fails. No compatibility obligation removes the migration *feature*; it does not remove the upgrade problem |
| J.13 | Execute the cutover on the live node | J.1–J.7, J.10–J.12 | The procedure is run for real, against the behaviour the other rows built rather than against a description of it. The seven records come back under their kinds with all six properties intact and the node serves normally afterwards. It cannot be marked complete before the rows it exercises exist, which is why it is separate from writing the runbook |
| J.14 | The compatibility migrations go | J.11 | `administrator_migration.go` renames `@maintainers` and parks a colliding group as `@administrators-legacy`; `EstablishDaemonOwner` and `EstablishAccounts` seed a "legacy or first" snapshot; the daemon accepts a pre-0.5.62 string where an array is now written. **No compatibility obligation before 1.1 makes all of it dead weight**, and J.11 already states what restore does with state it cannot read. Remove each, and with it the four `legacy` paragraphs in [setup](../../docs/09-setup.md) and [identity](../../docs/01-identity-and-roles.md) that are their only reason to exist. Restore any one migration and the check that the daemon refuses old state instead of converting it fails |
| J.8 | Docs own the new words | J.1–J.7, J.10–J.14 | [services and topics](../../docs/03-services-and-topics.md#how-to-call-it) splits: calling over the bus belongs to 👾, registering an external service to 📡. Glossary, [discovery](../../docs/05-discovery.md) and [glyphs](web/glyphs.md) name five kinds and no `generic`. Decision rows link the owning section and do not restate it. A sweep leaves no `generic`, no `mode` and no stale `📥`/`⚙️` as a record label anywhere outside history, and every anchor a moved heading breaks is repointed |
