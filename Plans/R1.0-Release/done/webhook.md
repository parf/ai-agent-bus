## Historical plan

The following pre-implementation plan is history. Later review replaced refuse-new/two pre-auth slots with six pre-auth slots, oldest-slow admission shedding, one-second first-byte/two-second header/five-second body budgets; two bus workers keep metadata responsive. The current guide owns the shipped behavior.

- ⏳ B.16 webhook — [defaults](../agents.md#next-set); xAB, now (owner, 2026-10-28: "do Webhook, Cron")
  - Acceptance: a POST to a configured URL reaches its configured queue or agent exactly once; an unknown URL, wrong Basic auth or a bad signature (where configured), an oversized body or an over-rate request is refused and delivers nothing; outbound calls only a configured URL
  - Mutant: accept wrong Basic auth, deliver to the wrong target or twice, or let a caller choose the outbound URL; a check must fail
  - **B.16 plan for read-only review (2026-10-28; no implementation yet):**
    - **Shape:** one Python-stdlib package `src/agents/webhook/`, kept (`serves:itself`, one bus worker), sandbox on with network enabled. One own bus identity receives outbound calls and sends accepted incoming bodies to its configured targets. No daemon/web changes, public deployment, new dependency or shared-provider behavior. Use the shared Python client, metadata ask dispatcher and env-file parser; do not use SIGALRM from HTTP worker threads.
    - **Configuration:** preserve the owner's root JSON **list of routes**, not a wrapper object. Each entry has a unique `name`; inbound entries have exact `path` and `target`, outbound entries have a fixed `url` (mutually exclusive forms). Optional inbound `basic` names a username and a password key; optional `signature` selects `github` or `stripe` and names its signing-key entry. Values live only in this record's **Secret**, parsed with the shared env-file rules; no host-env credential substitute. Outbound routes may also name Basic credentials, with Content-Type fixed by the route. No URL, target, auth header or signing key supplied by a caller overrides Configuration. Native help-config explicitly documents the root list; help-secret names referenced Secret entries without values. The manifest, generic .dist and guide will show the precise accepted fields/defaults before parser implementation is frozen.
    - **Listener/lifetime:** public non-secret `WEBHOOK_LISTEN` in env.dist defaults to loopback; the owner chooses the eventual address and reverse-proxy TLS. Outbound-only configurations bind nothing. Missing/invalid Configuration or required Secret leaves help/status available but binds no listener. Snapshot settings at start; runner reload applies changes. Bounded fixed HTTP workers (8), backlog, header/request-line and body reads with a single monotonic request deadline; no unbounded thread creation. SIGTERM/INT stops acceptance and boundedly drains workers. Status reports actual listener/configuration health, with no secrets.
    - **Incoming contract:** POST only, exact configured raw path; refuse query/encoded aliases, traversal, duplicate/framing headers, Transfer-Encoding and unexpected Expect handling before delivery. Content-Length required, strictly numeric, bounded before allocation; body is UTF-8 text, forwarded byte-for-byte as that text, never reserialized or wrapped. Default body cap 256 KiB (route may lower it); per-route token bucket defaults 60/minute with burst 10, with finite validated upper bounds and one locked state per configured route, not an unbounded client-IP map. Unknown URL, bad auth/signature, invalid UTF-8, oversize and over-rate all deliver nothing. No request headers/credentials forwarded. At each delivery verify the configured destination exists and is queue or agent, then invoke bus.send once under #webhook's own grants; no pubsub target or caller-supplied destination.
    - **Authentication:** strict single Authorization header, strict Base64 and constant-time comparison of expected Basic bytes. GitHub verifies `X-Hub-Signature-256` as HMAC-SHA256 of exact body bytes. Stripe verifies bounded `Stripe-Signature` t/v1 fields and HMAC-SHA256 of timestamp-dot-body with a 300-second freshness window; bound candidate signatures and reject conflicting/duplicate timestamp fields. Checks are independent: if Basic and HMAC are configured, both must pass. Missing referenced Secret fails closed. TLS is verified for outbound HTTPS; inbound HTTP is intended behind the owner's TLS reverse proxy.
    - **Delivery semantics:** one successful POST makes exactly one bus send and returns success only after definite acceptance. A definite bus refusal is a failure response; a timeout/drop after sending is explicitly an unknown outcome, never success, and the agent never automatically resends. A caller repeating an HTTP POST is a separate request and may duplicate it; no durable event-ID deduplication or cross-system exactly-once claim is invented. Tests count destination messages and backend invocations, not just the last body. The HTTP acknowledgment does not claim the destination processed the message.
    - **Outgoing calls:** `post <route> <body>` or strict JSON `{method:"post",route:"name",body:"UTF-8 text"}` selects a configured outbound route, with no caller URL or header fields. POST its body unchanged once using http.client, no proxy env, redirect or retry; configured HTTP(S) only, no userinfo/fragment/control injection. Named routes are the outbound authority boundary; intentionally configured private/loopback endpoints are allowed. Bound request/reply bytes, headers, DNS/connect/read and whole-call time by a monotonic deadline and the envelope deadline. A fixed package helper subprocess handles one outbound HTTP call via private stdin/stdout pipes; communicate timeout kills and reaps it, bounding DNS and trickle without thread-local SIGALRM. Strip inherited bus credentials/roles from its environment; never put auth values in argv. HTTPS uses the default verifying context. Return upstream status/body even for non-2xx. Mask Secret values and encoded Basic credentials in provider echoes, errors and logs; never report raw exceptions, URLs, headers or payloads. Logs hold route name, byte counts and result status only. A safe read-only `routes` method lists route names/directions, and asks dispatch before all ordinary work; unknown asks never trigger HTTP or bus delivery.
    - **Files/integration:** split bounded validation/auth, HTTP in/out and bus lifecycle code; agent.json, env.dist, config.json.dist, README, package.sh and focused tests. Self-contained package carries Python client, metadata/envfile helpers, shared version and licenses. Add explicit package/setup/release inventories and missing-file/outside-checkout fixtures; L shard `agent_webhook` has normal integration and a small explicit fast essential set. Coordinate shared smoke/package/setup/acceptance files with AB2's cron; preserve SMTP/IMAP/RAG/DB. Add docs/agents/webhook.md with all required headings, docs URL and generated index entry.
    - **Checks/mutants:** loopback fake HTTP/TLS only plus disposable daemon and real exported package. Prove one POST yields one exact message to its configured queue/agent; wrong route/auth/HMAC/timestamp, malformed framing, missing Secret, oversize, over-rate and wrong destination kind yield zero; concurrent HTTP requests stay bounded. Prove outbound exact origin/path/body, non-2xx pass-through, verified TLS, no redirects/retries, deadlines/caps and credential-echo redaction; unknown asks do no work. Golden GitHub/Stripe vectors, parser duplicate/extra-field/type/control tests and adversarial real socket cases. Compiling owning assertion-red mutants bypass Basic/HMAC/freshness/rate/caps, retarget/double-send, trust caller URL, follow redirect/retry, strip a configured limit or leak a Secret; package-required-file and reader-mode mutants. Each new check must show its owning failure, then restored green; no full-gate mutant runs.
    - **Review decisions (9ffa4aad):** take the delivery token only after framing, header-only Basic validation, bounded body read and HMAC/freshness all pass; bad requests never spend a route token. At most two unauthenticated requests may occupy workers at once (within eight total), with a 2-second header deadline and 5-second body deadline; at capacity refuse promptly rather than queue unbounded work. This bounds resource use, not immunity to an unlimited network flood; the reverse proxy owns network admission. Log at most ten failures/minute plus one bounded summary, with no unbounded source-IP table. Test 1000 bad Basic requests followed by a good request, and slow-header slots expiring while subsequent good requests progress.
    - **Replay/authority/header decision:** retain one bus send per HTTP request; no inferred delivery-ID dedupe (GitHub's delivery ID itself is unsigned, and equal bodies can be distinct events). The guide explicitly says GitHub/Basic requests can be replayed, Stripe requests within its freshness window can repeat, and cache-free restarts retain no replay history. ACL alone grants every configured outbound route and its stored authentication; default remains @owner, use separate instances for separate grantees. Incoming bodies are untrusted external data sent under the webhook identity; targets must allow that identity and handle the text accordingly. Deliberately forward body only: event-type/other HTTP headers are not mapped to tag/topic or wrapped without an owner format decision.
    - **Concurrency/helper/framing refinement:** the Python transport opens one connection per request, protects its active set/identity state with locks, and supports shared use. Test eight concurrent incoming sends plus an outbound call and help/status on the same real disposable bus. Use two bus handler workers and a nonblocking one-helper admission slot: a long outbound call occupies one, while other ordinary posts get busy promptly and metadata remains responsive. Parent reads helper stdout/stderr with select, a combined byte cap and absolute deadline (not unbounded communicate); process-group kill/reap on cap/deadline, stripped environment, fixed argv and private stdin. All responses close the connection. Reject absolute-form targets, obs-fold, duplicate Host/Content-Length/Authorization/signature headers, TE, all Expect, non-HTTP/1.0 or 1.1 and pipelining. Unknown paths and failed authentication share one generic 404 response with no WWW-Authenticate; no route/path/body/credential data in failure logs.

Secret values are UTF-8 text, one key per signature route (no rotation overlap); missing/invalid reference invalidates the whole Configuration and binds nothing. GitHub signature is lowercase sha256= plus exactly64 hexadecimal digits (accept hex case by decoding to bytes), constant-time bytes compare.
