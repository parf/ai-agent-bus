# M.11 real-host acceptance

📌 **TL;DR:**
- **Result:** every system-runner verb of `agent-bus-setup --runner` ran on a real systemd host (a disposable rootless-podman container, 0.9.262 release archive) and left it as [the setup guide](../../../docs/07-setup.md#a-persons-runner) states: 38 checks passed, 0 failed.
- **Covered:** install, a second install (changes nothing), enable, disable, uninstall, uninstall `--purge`, plus a refused non-User; after each verb the account, unit, template, private directory, bus record and shared `agent.d` were read back.
- **Evidence:** the [unaltered check log](m11-real-host-2026-11-01.log), SHA-256 `b3379bf505bb780f84069e1f571bcf39961c5126edb1546e34f7f27b7bb50ccb`.

## How it ran

- **Host:** `podman run --privileged --systemd=always --network=none` from `src/acceptance/fresh-install.Containerfile` (Arch, real `/sbin/init`), on this node, rootless, under the smoke-gate slow lock taken only around the podman steps.
- **Build under test:** `src/package.sh` of `main` at 07a3422c, version 0.9.262, installed by the archive's own `agent-bus-setup --owner owner@fresh`; the container saw only the archive, the fixture script and an evidence directory, never the checkout.
- **Person:** a bus User `alice` added with `agent-bus-admin user add alice`; a marker file in `/var/lib/agent-bus/agent.d` stood for the shared agents.
- **Checks:** after each verb the script printed the host state (account and shell, unit enabled/active, template, private directory, `runner.env`, the `#runner/alice@<host>` record, shared `agent.d`) and asserted it.

## What each verb left

| Verb | Observed |
|---|---|
| `--dry-run` | printed the six steps (account, directory, template, record, `runner.env`, enable and start); nothing existed afterwards |
| `install` | account `alice-ab-runner` with `/usr/sbin/nologin`; `/var/lib/agent-bus/alice-ab-runner` `alice-ab-runner:alice-ab-runner` 0700; `runner.env` 0600; template `agent-bus-runner@.service` (`User=%i-ab-runner`, only its private directory writable, `Wants=`/`After=` the daemon, no `Requires=`); the unit enabled and active, its process running as `alice-ab-runner`; the record present |
| second `install` and its `--dry-run` | "alice's runner: nothing to change"; `runner.env` hash and time, template time and the active unit unchanged |
| `disable` | unit disabled and inactive; account, directory, `runner.env` and template kept; shared `agent.d` kept; a second `disable` changes nothing |
| `enable` | unit enabled and active again |
| `uninstall` | no account, no directory, no template (the last runner), no enabled unit, the record removed; shared `agent.d` and its marker kept; a second `uninstall` changes nothing |
| `install` then `uninstall --purge` | same end state as `uninstall`; shared `agent.d` kept even with `--purge` |
| `install --for nosuchperson` | refused ("not an active bus User"), no account created |

## Findings

- **No doc or code difference found:** each verb matched the setup guide and the [M.11 acceptance](../TODO.md#runner-waves) (each verb leaves the stated state, a second run changes nothing, uninstall leaves nothing but keeps shared `agent.d`, a non-User is refused).
- **The first runs were red for harness reasons (their logs were not retained; the check did fail when it should):** a bus User named `alice@fresh` is not the plain-name User `--for alice` finds, so install was refused ("alice is not an active bus User"); the record check read the active listing, which omits a record whose runner is stopped; `cmp` is absent from the Arch image, so the unchanged-`runner.env` check compared SHA-256 instead.
- **Not covered:** a real agent served by the installed runner, and a Debian host (the container is Arch on this x86_64 node).

## Cleanup

The container ended with the run (`--rm`, none left); the two images this run created, `localhost/agent-bus-m11:arch-systemd` (0b28f27af8d1) and the pulled `docker.io/library/archlinux:latest` (bf2533a05fd2), were removed by ID; no other image or container was touched.
