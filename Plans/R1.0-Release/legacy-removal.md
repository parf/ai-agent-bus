# Remove prerelease compatibility before R1

📌 **TL;DR:** Remove obsolete prerelease input forms, storage conversions and installation adapters before R1 ships.
Keep current recovery, authority, message delivery and supported external protocols intact.
This is a proposed implementation plan and source inventory, not evidence that the development node has been converted.

## Scope

The owner moved this work into R1 and stated that no release has been made.
There is no `Plans/R1.0.1/` directory; the former deferral appears in
`Plans/doc-cleanup-rules.md`, not in a separate release plan.
Historical release labels in comments do not establish an external support obligation.

Inventory baseline: `01dbbb77`. Production branches, callers and regression fixtures were read;
no daemon, database, installed file, provider or running session was queried or changed.
“Used” below means a current source caller or fixture, never a verified live installation.
Every state-dependent removal therefore needs a development-node preflight before deployment.

The target is one R1 representation and installation layout. A converter needed only for the
development node belongs in a separately reviewed, temporary operation, not in shipped runtime
startup. Do not replace a conversion with silent deletion, reinitialization or replay.
Reject unsupported persisted state clearly before serving or making changes.

## Order and acceptance

1. **Freeze the supported boundary and conversion inputs.** Confirm this inventory against the final R1 tree; enumerate every removed input and required current alternative. Inspect the development node read-only in a separate authorized operation, recording counts and shape/version markers without tokens, secrets or message bodies. Identify active sessions, pending conversion/upgrade journals and retained rollback targets. The code inventory does not authorize deleting them.
2. **Prepare and review the one-off conversion.** Use a private stopped-state copy and preserve rollback material. Convert database/snapshot identities and tags before the new decoder; convert agent KV rows/claims and sessions before removing their readers. A current export omits queues and other runtime state, so exporting/reimporting alone is not a full-node preservation strategy. Test interrupted conversion and collision refusal on copies; reconcile all uncertain delivery evidence before resuming.
3. **Cut over wire producers and consumers together.** Personal tag authority first, then field removal, Maintainer arrays and live reader metadata. Update daemon, CLI, runner, MCP, web, launchers, six SDKs, fixtures and documentation in dependency order. Preserve the [authority boundary](../../docs/02-access.md#trust-boundary) and [current messaging contract](../../docs/04-messaging.md#durability). Do not silently accept retired fields while pretending they were honored.
4. **Remove storage and installer adapters.** Current-schema-only load, no startup format conversions, no obsolete bundle/layout/flag exceptions. Keep current initialization, generic strict validation, transactional replacement and interrupted-current-install recovery. Remove orphaned imports, exported package files and manifest allowances with the code.
5. **Remove agent/session migrations and old routes.** Finish the corresponding one-off conversions before deploying each affected component. Keep current queues/routes/claims and reject unsupported leftovers. Rewrite first-party scripts and generated units before rejecting single-dash long flags.
6. **Independent review and acceptance.** Review each subsystem against the repository checklist, including a second authority/install/storage reviewer where required. Prove each new refusal test fails on the prior implementation. For new checks and changes in the marked sensitive subsystems, run a compiling reverse mutant that fails the owning assertion; parser rejection or build failure does not prove a behavioral mutation. Run focused current-behavior regressions as well as old-input rejection. Then run the required normal gate and eventual release-wide slow gate under the [gate rules](../../CLAUDE.md#verification), with lock ownership and cleanup. No gate or mutation was run for this planning document.

Completion requires a current-format round trip for records, credentials, account mappings,
KV, queue checkpoint state, event subscriptions/alerts and agent progress; clean first install;
current-to-current upgrade and interrupted recovery; all six SDKs plus CLI/MCP interoperability;
and package inventories containing no removed helpers. Historical fixture names may remain only
where they explicitly prove rejection, not where a deleted branch's test was simply removed.

The implementation report must list actual conversion counts, refusal cases, regression and

## Limits and remaining checks

The source sweep covered `src/internal`, `src/cmd`, `src/launchers`, `src/mcp`, all six
`src/clients` implementations, `src/agents`, `src/web`, packaging and acceptance references.
Search terms included legacy, deprecated, backward compatibility, migration, old format,
fallback and aliases; vendor/minified assets and historical Markdown were classified separately.
Named candidates were traced to production callers and representative fixtures. This is a
bounded source inventory, not proof that every unlabeled compatibility branch or external
caller has been found. Repeat the sweep and inspect serialization defaults when implementing
each subsystem; add evidence for any newly discovered family before removing it.

Unknowns blocking destructive conversion are the live database/schema and snapshot markers,
old agent rows and unfinished journals, active launcher lock/binding formats, old timer units,
retained rollback packages, and external scripts still supplying old flags/fields. None was
measured here. Third-party runtime support and valid unmarked reply behavior must not be
silently reclassified as obsolete to make a zero-match search pass.
